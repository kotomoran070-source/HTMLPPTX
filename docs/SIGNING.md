# Подпись приложения

## Коротко

**Что это.** Подпись — отметка в файле: «собрал такой-то, и с тех пор файл не меняли». Код она не прячет и не шифрует.

**Что она даёт:**
- Windows показывает в окне запуска ваше имя вместо «Неизвестный издатель».
- Любая правка подписанного файла ломает подпись, и это видно в его свойствах.
- Проверка целостности программы держится на ней: отпечаток кода вшит в `Slideria.exe`, а подпись не даёт подменить его незаметно. Подробнее — в разделе «Подпись и защита кода» ниже и в [PROTECTION.md](PROTECTION.md).

**Что делает сборка.** `yarn app:build` подписывает `Slideria.exe`, `elevate.exe`, установщик и деинсталлятор. К подписи добавляется метка времени, поэтому подпись остаётся действительной и после окончания срока сертификата. Для метки во время сборки нужен интернет.

**Где сертификат.** Сборка берёт его из переменных окружения, в проект он не попадает:
- переменных нет — установщик собирается без подписи;
- сертификат задан, но подписать не вышло — сборка останавливается, чтобы неподписанный установщик не проскочил случайно.

| Переменная | Что в ней |
|---|---|
| `SLIDERIA_CERT_SHA1` | Отпечаток сертификата из хранилища Windows: на токене или один раз импортированного `.pfx`. Не секрет: ключ остаётся в хранилище |
| `CSC_LINK` и `CSC_KEY_PASSWORD` | Файл `.pfx` (путь к нему или содержимое в base64) и пароль. Так сертификат передают в GitHub Actions |

## Какой путь выбрать

| Задача | Сертификат | Что увидят другие люди | Цена |
|---|---|---|---|
| Проверить, что подпись работает | Свой (самоподписанный) | «Неизвестный издатель», как без подписи: свой сертификат знает только ваш компьютер | Бесплатно, 5 минут |
| Раздавать программу | Сертификат подписи кода от центра сертификации на токене (USB-ключ) | Ваше имя или название организации | Платно, оформление — от нескольких дней |
| Собирать и подписывать в GitHub Actions | Облачная подпись: Azure Artifact Signing или облако центра сертификации | То же, что у сертификата центра | Платно |

С 2023 года ключ подписи кода выдают только на токене или в облаке центра сертификации, файлом `.pfx` настоящий сертификат не получить. Что доступно в вашей стране и сколько стоит, уточняйте у продавца до оплаты.

**SmartScreen.** Даже с настоящим сертификатом первое время Windows может показывать предупреждение SmartScreen. Оно уходит, когда у файлов накопится репутация: их скачивают и запускают без жалоб. Сертификат EV больше не убирает это предупреждение сразу.

## Подпись на своём компьютере

### Шаг 1. Сертификат

**Свой, для проверки.** В PowerShell, права администратора не нужны:

```powershell
$cert = New-SelfSignedCertificate -Type CodeSigningCert -Subject "CN=Slideria Test" `
  -CertStoreLocation Cert:\CurrentUser\My -KeyAlgorithm RSA -KeyLength 3072 -HashAlgorithm SHA256 `
  -NotAfter (Get-Date).AddYears(3)
$cert.Thumbprint
```

Чтобы ваш компьютер доверял этому сертификату (только для проверки и только на своём компьютере):

```powershell
Export-Certificate -Cert $cert -FilePath "$env:TEMP\slideria-test.cer"
Import-Certificate -FilePath "$env:TEMP\slideria-test.cer" -CertStoreLocation Cert:\CurrentUser\Root
Import-Certificate -FilePath "$env:TEMP\slideria-test.cer" -CertStoreLocation Cert:\CurrentUser\TrustedPublisher
```

Windows спросит, установить ли корневой сертификат, — ответьте «Да». Убрать его потом: `certmgr.msc` → «Доверенные корневые центры сертификации» и «Доверенные издатели» → «Slideria Test» → удалить.

**Настоящий, на токене.** Вставьте токен и посмотрите отпечаток:

```powershell
Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert | Format-List Subject, Thumbprint
```

### Шаг 2. Сказать сборке, каким сертификатом подписывать

Один раз, затем откройте терминал заново:

```powershell
[Environment]::SetEnvironmentVariable('SLIDERIA_CERT_SHA1', 'отпечаток', 'User')
```

Отпечаток можно скопировать и из окна сертификата: «Состав» → «Отпечаток». Невидимый символ в начале и пробелы сборка уберёт сама.

Вместо хранилища можно взять файл `.pfx`, только на время сеанса терминала. Держите файл вне папки проекта:

```powershell
$env:CSC_LINK = 'C:\keys\slideria.pfx'
$env:CSC_KEY_PASSWORD = 'пароль'
```

### Шаг 3. Собрать

```powershell
yarn app:build
```

В начале сборка пишет, чем подписывает: «Подпись: сертификат … из хранилища Windows». Готовый установщик — в `dist-app`.

### Шаг 4. Проверить

```powershell
Get-AuthenticodeSignature "dist-app\Slideria Setup 0.1.0.exe" | Format-List Status, StatusMessage, SignerCertificate, TimeStamperCertificate
```

| Status | Что значит |
|---|---|
| `Valid` | Подпись в порядке, и компьютер ей доверяет |
| `UnknownError` и «…root certificate which is not trusted» | Подпись в порядке, но этот компьютер сертификату не доверяет: свой сертификат без шага «доверять» |
| `NotSigned` | Подписи нет |
| `HashMismatch` | Файл меняли после подписи |

То же видно в проводнике: «Свойства» файла → «Цифровые подписи». Проверьте и сам `Slideria.exe` после установки.

## Подпись и защита кода

Сборка прячет код и защищает его от правки ([PROTECTION.md](PROTECTION.md)): сжатый код, `app.asar`, проверка целостности. Отпечаток `app.asar` вшит в ресурсы `Slideria.exe`.

- **Неподписанный `.exe`:** его можно поправить вместе с отпечатком, и программа этого не заметит.
- **Подписанный `.exe`:** после такой правки подпись ломается, и Windows это видит.

Проверка целостности по-настоящему работает только вместе с подписью.

## Если что-то не так

| Что видно | Причина и что делать |
|---|---|
| После подписи своим сертификатом всё равно «Неизвестный издатель» | Так и должно быть: свой сертификат знает только ваш компьютер |
| Сборка остановилась на подписи | Проверьте, что токен вставлен, что отпечаток в `SLIDERIA_CERT_SHA1` совпадает с сертификатом и что есть интернет (нужен для метки времени) |
| Токен спрашивает PIN на каждый файл | Так работает драйвер токена: подписывается несколько файлов, и PIN могут спросить для каждого |
| Сборка пишет «Без подписи», а сертификат есть | Терминал открыт до того, как задали переменную. Откройте его заново |

## Потом: GitHub Actions

Сборке нужны те же переменные, только из секретов репозитория (Settings → Secrets and variables → Actions).

**Свой сертификат, для проверки.** Сохраните сертификат из шага 1 в файл и переведите в base64:

```powershell
Export-PfxCertificate -Cert $cert -FilePath C:\keys\slideria-test.pfx -Password (Read-Host -AsSecureString "Пароль")
[Convert]::ToBase64String([IO.File]::ReadAllBytes('C:\keys\slideria-test.pfx')) | Set-Clipboard
```

Скопированное положите в секрет `WIN_CSC_LINK`, пароль — в `WIN_CSC_KEY_PASSWORD`. Шаг сборки:

```yaml
runs-on: windows-latest
steps:
  - uses: actions/checkout@v4
  - uses: actions/setup-node@v4
    with: { node-version: 20 }
  - run: yarn install --frozen-lockfile
  - run: yarn app:build
    env:
      CSC_LINK: ${{ secrets.WIN_CSC_LINK }}
      CSC_KEY_PASSWORD: ${{ secrets.WIN_CSC_KEY_PASSWORD }}
  - uses: actions/upload-artifact@v4
    with: { name: Slideria, path: dist-app/*.exe }
```

**Настоящий сертификат.** Токен в сервер GitHub не вставить. Есть два пути:
- **Облачная подпись:** Azure Artifact Signing (в electron-builder — `win.azureSignOptions`) или облако центра сертификации. Подключается, когда сертификат уже выбран.
- **Свой компьютер:** сборка в GitHub Actions на своём компьютере с вставленным токеном (self-hosted runner). Шаг сборки тот же, только `runs-on: self-hosted`, а `SLIDERIA_CERT_SHA1` задан на этом компьютере.
