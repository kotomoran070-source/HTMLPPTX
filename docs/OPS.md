# Операции правки

Как править презентацию не руками в студии, а командами: агент (Claude), MCP, плагины. Операция — один шаг правки
с проверкой и подписью («Правка объекта · слайд 3»). Код — `src/engine/ops.ts`: чистые функции над данными,
какими они лежат в `deck.yaml`, без страницы и файлов. Сервер (`server/core.ts`) читает, применяет и записывает.

Интерфейс студии операции пока не трогают: в студии всё как было. Правка агента приходит в открытую студию так же,
как правка из второго окна, и Ctrl+Z студии откатывает только свои правки (см. «Вместе со студией»).

## Как агент правит

1. **Читает краткое содержание** — `outline`: слайды с номерами, id и ревизиями, у слайда — заголовок, заметки,
   блоки раскладки и свободные объекты с номерами, именами, первым текстом и местом. Один слайд целиком —
   `outline` со `slide`: данные как в `deck.yaml`.
2. **Отправляет пакет операций** — `apply`: список операций и ревизии слайдов, которые правит (`expect`).
   Пакет применяется целиком или не применяется вовсе. В ответе — подписи правок и новое краткое содержание:
   можно продолжать без перечитывания.
3. **Слайд с тех пор поменяли** (в студии, другим агентом) — отказ «Слайд 3 изменился с тех пор, как его прочитали.
   Перечитайте (outline) и повторите», файл не тронут. Правки других слайдов не мешают.

```jsonc
// POST /__htmlpptx/outline?deck=report
{ "title": "Итоги", "theme": "midnight", "slides": [
  { "n": 1, "id": "cover", "rev": "0k3j9x2a", "template": "cover", "title": "Итоги квартала", "notes": "…" },
  { "n": 2, "id": "idea", "rev": "1p8d0c7q", "template": "canvas",
    "objects": [
      { "n": 1, "type": "text", "text": "Главная мысль", "place": { "x": 80, "y": 80, "w": 600 } },
      { "n": 2, "type": "shape", "name": "box", "text": "Компания", "place": { "x": 700, "y": 300, "w": 200, "h": 120 } } ] } ] }

// POST /__htmlpptx/apply?deck=report
{ "ops": [
    { "op": "object.set", "slide": "idea", "object": "box", "set": { "text": "Slideria", "place": { "x": 100 } } },
    { "op": "slide.add", "slide": { "title": "Цифры", "body": [{ "type": "stat", "value": "+12 %", "label": "выручка" }] }, "at": 3 } ],
  "expect": [{ "slide": 2, "rev": "1p8d0c7q" }] }
// → { "changed": true, "changes": ["Правка объекта · слайд 2", "Новый слайд 3"], "outline": { … } }
```

## Адреса

- **Слайд** — номер с 1 (как «3 из 14» при показе) или `id` слайда. Номера считаются после предыдущих операций
  того же пакета; id от перестановок не зависит.
- **Объект** — свободный объект слайда (`free`): номер с 1 снизу вверх (больший лежит поверх) или имя (`id`
  объекта — то же имя, что в «Области выделения» и у пары морфа).
- **Ревизия** (`rev`) — 8 знаков, отпечаток данных слайда; от порядка полей не зависит.

Имена объектам не раздаются: имя — это пара для морфа (объекты с одним именем на соседних слайдах перелетают друг
в друга), а у объектов без имени пару находит содержимое. Автоматические имена сломали бы морф и появились бы
в «Области выделения». Номер с ревизией надёжен так же: если слайд поменяли, ревизия другая — агент перечитает.

## Операции

Поля в `set` — слиянием (JSON Merge Patch, RFC 7386): объекты сливаются по полям, `null` удаляет поле, остальное
(и списки) заменяется. `{ "place": { "x": 100 } }` сдвигает объект, не меняя размер.

| Операция | Поля | Что делает |
|---|---|---|
| `deck.set` | `set` | поля презентации: `title`, `lang`, `brand`, `theme`, `fonts` (слайды — нельзя) |
| `slide.add` | `slide`, `at` | новый слайд (данные как в `deck.yaml`; без них — пустой холст) на место `at` или в конец; id без повторов, без id — `slide-2`, `slide-3`… |
| `slide.remove` | `slide` | удалить слайд (единственный — нельзя) |
| `slide.move` | `slide`, `to` | переставить на место `to` |
| `slide.duplicate` | `slide`, `at` | копия слайда (сразу за ним или на `at`); имена объектов те же — морф с оригиналом работает сразу |
| `slide.set` | `slide`, `set` | поля слайда: `title`, `notes`, `template`, `transition`, `hidden`, `body`… (`free` — нельзя: объекты — операциями `object.*`) |
| `object.add` | `slide`, `object`, `at` | новый свободный объект (`type` обязателен, как в `free`) поверх всех или на место `at` в стопке |
| `object.set` | `slide`, `object`, `set` | поля объекта: `place`, текст, оформление, анимация |
| `object.remove` | `slide`, `object` | удалить объект |
| `object.order` | `slide`, `object`, `to` | место в стопке: `"front"`, `"back"` или номер |
| `text.replace` | `find`, `replace`, `slide` | заменить текст (точное совпадение) в заголовках, текстах, пунктах, ячейках, заметках — на одном слайде или везде, включая название презентации; имена, пути к файлам и стили не трогаются |

Справочник полей слайдов и объектов — [COMPONENTS.md](COMPONENTS.md), как писать презентацию —
[skills/slideria-deck](skills/slideria-deck/SKILL.md). Картинка в поле как `data:` (base64) при записи становится
файлом в `assets/`, как у студии.

**Проверка итога.** После операций данные проверяются: хотя бы один слайд, у слайда — объект, id слайдов без повторов,
у объекта — `type`, `place` — числа, имя объекта на слайде одно. Проверяются только новые и поправленные слайды:
старые данные, поправленные руками, не мешают править остальное. Ошибка — с номером операции и тем, что не так:
«Операция 3 (object.set): нет объекта 7 на слайде 2: объекты — с 1 по 5».

## Вместе со студией

- Запись — как у окна студии: комментарии в `deck.yaml` сохраняются, открытые окна получают событие и подтягивают
  правку сами (тот же путь, что у заметок из окна докладчика).
- Студия и агент правят **разные объекты одного слайда** одновременно — остаются обе правки: объекты сливаются
  по одному, если состав слайда тот же (`src/engine/merge3.ts`). Одно и то же поле — побеждает окно, которое
  записывает последним. Добавили или переставили объекты — список целиком из записывающего окна, как раньше.
- **Ctrl+Z в студии** откатывает только свои правки: правка агента переносится в шаги истории студии, вплоть
  до поля отдельного объекта (`src/engine/editor/history.ts`).

## Команды сервера

`core.outline(name, { slide? })`, `core.apply(name, { ops, expect?, from? })` (`server/core.ts`); по HTTP —
`POST /__htmlpptx/outline?deck=имя[&slide=n|id]` и `POST /__htmlpptx/apply?deck=имя` с JSON `{ ops, expect }`
([SERVER.md](SERVER.md)). Ошибка — `{ error }` с кодом 400. `from` — кто правит (по умолчанию `agent`): окна
студии видят его в событии `saved`.

Пока нет: адресов внутри групп и блоков раскладки (`body` правится целиком через `slide.set`), операций
для таблиц и графиков по ячейкам. Что дальше — [PLAN.md](PLAN.md).
