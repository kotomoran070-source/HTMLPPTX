# Сервер Slideria

Всё, что страницы делают с презентациями на диске, — в `server/`, без Vite. Одним и тем же сервером работают
программа (`desktop/main.mjs`), `yarn serve`, сервер разработки (`yarn dev`), команды для MCP, а дальше — облако.

**Программа — без Vite** (шаг В, [PERF.md](PERF.md)). Студия собрана заранее (`scripts/build.mjs --app` →
`studio/`: обычные файлы с отпечатком в имени, части студии грузятся по мере надобности), сервер — одним файлом
(`server.mjs`, его сторонние библиотеки — только из `dependencies`: сборка это проверяет). Программа запускает
его (`server/serve.ts`) и открывает окно. В установщике нет ни исходников, ни Vite, ни библиотек страниц — они
внутри сборки студии (`docs/PROTECTION.md`).

**`yarn dev`** — тот же сервер внутри Vite (`plugins/decks.ts`): Vite только отдаёт исходники страниц и обновляет
их при правке кода. Данные, уведомления и слежение за файлами — те же модули, что у программы; страницы получают
данные одинаково на обоих путях (`src/engine/deck-source.ts`), поэтому тесты одного пути проверяют и другой, а
`SLIDERIA_SERVE=1` гоняет те же тесты на сервере программы.

```
server/serve.ts       сервер программы: собранная студия, файлы презентаций, уведомления, слежение — на node:http
server/core.ts        ядро: презентации, запись со слиянием, точки, файлы, шрифты, библиотека, импорт, экспорт
server/http.ts        HTTP: защита адреса, пульт, «Лицензии», данные для страниц, команды /__htmlpptx/*
server/events.ts      уведомления страницам: свой WebSocket (только сервер → страница, только этому компьютеру)
server/watch.ts       слежение за папкой презентаций: правка deck.yaml со стороны, новые и пропавшие презентации
server/frame-host.ts  адрес для слайдов со звуком (отдельный порт, одна пустая страница)
server/player.ts      готовый проигрыватель для экспорта в HTML: варианты, кэш, сборка недостающего
server/mcp.ts         MCP для агентов: инструменты и протокол без транспорта (docs/MCP.md)
server/running.ts     какой сервер студии работает с папкой презентаций (для MCP)
server/integrations.ts агенты на связи, что им можно, журнал правок, скрипты (docs/INTEGRATIONS.md)
server/deck-files.ts  файлы презентаций: папки, deck.yaml, пути к файлам в данных
server/host-guard.ts  защита от подмены адреса (DNS rebinding)
```

Сторож в `tests/unit/server.spec.ts`: в `server/` нет Vite, а сервер поднимается на голом `node:http` и отвечает;
`tests/unit/serve.spec.ts` — сервер программы целиком.

## Сервер программы

```ts
import { startServer } from './server/serve';

const s = await startServer({
  dir: 'presentations', root: process.cwd(), studio: '.tmp/app/studio',
  port: 47320,                                   // занят — любой свободный
  env: { app: true, decks: 'Документы/Slideria/' },
});
console.log(s.url);                              // http://127.0.0.1:47320
await s.close();
```

`startServer({ dir, root, studio, fonts?, library?, playerCache?, host?, port?, env?, bundled?, lan?, firewall?, run?, log? })`.
Слушает только этот компьютер (`127.0.0.1`), если не сказано иное. Что отдаёт, кроме обработчика `createHandler`:

| Адрес | Что |
|---|---|
| `/`, `/index.html` | страница студии; в неё вписаны `<meta name="slideria-env">` — программа ли это и как называть папку с презентациями (`src/engine/env.ts`), и адрес для слайдов со звуком; и подсказки браузеру (`codeHints`): по списку сборки (`.vite/manifest.json`) — `modulepreload` и стили частей студии, когда открывают студию, и заранее (`prefetch`) — на странице выбора |
| `/assets/…` | код и стили студии: имя с отпечатком содержимого — кэш навсегда; песочнице скриптов — запрет сети (`WORKER_CSP`) |
| `/@fs/…`, от корня | файлы презентаций и библиотеки шрифтов — те же адреса, что выдаёт ядро (`urlOf`) и что в `yarn dev`; только из этих двух папок и без служебных `.папок`; с проверкой «не изменился ли» (`ETag` → 304) и кусками (`Range` → 206: видео перематывается, не скачиваясь целиком) |
| `/__slideria/events` | уведомления (WebSocket) |

`yarn serve` (`scripts/serve.mjs`) — то же из командной строки: собирает код, если он поменялся, и запускает.

## Уведомления страницам

`server/events.ts` — свой WebSocket без библиотек: страница подписывается (`onServer(type, fn)`,
`src/engine/events.ts`), сервер рассылает. WebSocket, а не поток событий: браузер держит к одному серверу не больше
шести обычных соединений на все вкладки, а студия, показ, докладчик и пара вкладок заняли бы их навсегда.

| Событие | Когда | Кто слушает |
|---|---|---|
| `deck-saved` `{ name, from }` | презентацию записали (окно, агент, MCP) | редактор: подтянуть чужую правку |
| `deck-removed` `{ name }` | презентацию убрали в корзину | страница выбора — убрать карточку; открытая — к списку |
| `deck-changed` `{ name, rev }` | `deck.yaml` поправили со стороны (текстовый редактор, git); `rev` — версия файла теперь | открытая презентация — заново, если её версия другая (`X-Slideria-Rev` при чтении); страница выбора — обновить карточку |
| `decks` `{ added, removed }` | папки презентаций положили или убрали руками | страница выбора — заново |
| `agents`, `journal` | агенты на связи, правка агента в журнале | «Интеграции», подсказка на холсте |
| `reconnected` (на странице) | связь вернулась после обрыва | редактор: сверка с файлом |

Только этому компьютеру и только своим страницам: чужое имя сервера, чужой `Origin` и телефон в сети получают
отказ. Своя запись сервера правкой «со стороны» не считается (`wrote`/`ownWrite` ядра).

**Слежение** (`server/watch.ts`) — за самой папкой презентаций и за каждой папкой презентации, без вложенных:
картинки, корзина и контрольные точки бывают большими, а нужны только `deck.yaml`. Перед переносом в корзину
ядро отпускает папку (крючок `release`): Windows не даёт переименовать папку, за которой следят.

## Подключить к любому серверу

```ts
import http from 'node:http';
import { createDecksCore } from './server/core';
import { createHandler } from './server/http';

const core = createDecksCore({ dir: 'presentations', root: process.cwd() });
const handle = createHandler(core);
http.createServer((req, res) => handle(req, res, () => { res.statusCode = 404; res.end(); })).listen(5190, '127.0.0.1');
```

`createHandler` пропускает дальше (`next`) всё, что не его: страницы и код отдаёт хозяин.

## Ядро

`createDecksCore({ dir, root, fonts?, library?, urlOf?, playerCache?, hooks? })`:

| Что | Методы |
|---|---|
| Презентации | `names()`, `has(name)`, `list()` — с временем правки и сводкой (название, число слайдов, откуда импортирована, «файл не читается»; помнит её, пока файл не менялся), `read(name, { urls })` — данные (с `urls` — пути к файлам адресами для страницы), `create(title, sample)` — из `templates/basic`, `trash(name)` — в `.trash`, не насовсем |
| Операции правки | `outline(name, { slide? })` — краткое содержание для агента: слайды с ревизиями, объекты с номерами; `apply(name, { ops, expect?, from? })` — пакет операций, все или ни одной ([OPS.md](OPS.md)) |
| Запись | `save(name, { deck, base, from })` — трёхстороннее слияние с файлом: из окна берётся только то, что оно поменяло само; чужие правки возвращаются окну; комментарии в YAML сохраняются |
| Контрольные точки | `checkpoint(name, { kind })`, `checkpoints(name)`, `readCheckpoint(name, id)` — копии в `.checkpoints`: свои (Ctrl+S, последние 30), `session/` — когда открыли и «Сохранить» при выходе (30), `auto/` — до и после правки агента и скрипта (30 дней), `dropped/` — «Не сохранять» при выходе (30 дней); виды и сроки — вверху `server/core.ts`. `discard(name, to)` — файл как в точке to, отброшенное — точкой `drop:`. В корзину — вместе с презентацией (`.history` в её папке), вернули папку — вернулись на место |
| Файлы презентации | `assets(name)`, `addAsset(name, fileName, data)` — тот же файл не повторяется, STL и STEP — в GLB, `writeAssetText` — код живой вставки, `trashAssets` |
| Шрифты | `fonts()`, `addFont(fileName, data)`, `useFont(name, file)` — только разрешённые автором к встраиванию |
| Своя библиотека | `library()`, `putLibrary(kind, id, value)`, `deleteLibrary(kind, id)` — темы, шаблоны, эффекты, образы |
| Импорт | `importPage(html, …)` — HTML, `importPowerPoint(data, …)` — PPTX, `bindTheme(name, dry)` |
| Экспорт | `exportHtml(name, { clean, compact, look, motion })` — один HTML-файл из готового проигрывателя; `fileHtml(html, name)` — данные и файлы внутрь страницы; `warmPlayers()` — собрать недостающие варианты заранее |
| Записи сервера | `wrote(file)`, `ownWrite(file, now)` — изменение файла сделал сам сервер: страницу не перезагружать |

Ошибки — исключения с понятным текстом для человека; неудачная сборка экспорта — `ExportError`.

**События** (`core.on(type, fn)`): `saved` — `{ name, from }`, записали презентацию (`from` — окно, которое
записало); `removed` — `{ name }`, презентацию убрали в корзину; `agents` — список агентов (подключился, замолчал,
правил); `journal` — новая запись журнала правок. Хозяин рассылает их страницам.

**Крючки хозяина** (`hooks`, все необязательны): `release(paths)` — отпустить наблюдение за папкой на время
переноса в корзину (Windows не даёт переименовать папку под наблюдением), возвращает функцию «снова следить»;
`run(script, args, opts)` — чем запускать сборку недостающего варианта проигрывателя (в программе — служебным
процессом Electron).

## Экспорт: готовый проигрыватель

Файл экспорта — страница проигрывателя (код показа, стили, шрифты интерфейса) и данные презентации со встроенными
файлами. Код показа не зависит от презентации, поэтому собирается не на каждый экспорт, а один раз на **вариант**:

| | |
|---|---|
| `show` / `edit` | только показ или с режимом правки в файле |
| `-3d` | 3D-модели (около 1 МБ) — только если в презентации есть `type: model` |
| `-math` | формулы (около 350 КБ с шрифтами) — только если есть `type: math` |

Восемь вариантов: `show`, `show-math`, `show-3d`, `show-3d-math`, `edit`, … `edit-3d-math`. Экспорт:

1. **Вариант** — по `deck.yaml` и режиму (`variantOf`). Где он берётся, по порядку: `<root>/player/` — собранные
   вместе с программой (установщик, `scripts/app-stage.mjs`); кэш `playerCache` (по умолчанию
   `node_modules/.cache/slideria-player`, в программе — в её данных), если отпечаток исходников (`sourceHash`:
   `src/`, `index.html`, конфиг Vite, плагины сборки, `package.json`, `yarn.lock`) тот же; иначе вариант собирается
   отдельным процессом (`scripts/build.mjs --player=<вариант>`, Vite) — один раз, одновременные экспорты ждут одну
   сборку. Код поменялся — варианты в кэше собираются заново по мере надобности, устаревшие удаляются.
2. **Данные** (`fileHtml`): данные презентации и исходная версия — в `<body>`, файлы — внутрь (`data:`), с «Компактным» —
   картинки в WebP; заголовок, язык и `<meta name="slideria-deck">` — имя, под которым проигрыватель хранит своё
   (ответы теста, правки в копии файла). Теги ищутся вне `<script>` и `<style>`: в коде проигрывателя такие строки тоже есть.
3. **Отделка** (`finishFile`): «Как на этом компьютере» — `data-slideria-look` у `<html>` (вид слайдов) и запросы
   «Уменьшить движение» во всём файле отвечают «движение можно»; блок лицензий — библиотеки варианта (список рядом
   с ним, `<вариант>.json`) и шрифты комплекта, которые оказались в файле.

`yarn build` делает то же из командной строки; `yarn build --players --out=папка` — все варианты сразу.

## HTTP

`createHandler(core, { allowedHosts?, address?, lan?, firewall?, log?, bundled? })`, по порядку:

1. **Защита адреса.** Чужое имя сервера (DNS rebinding) — отказ раньше всех обработчиков. Свои — `localhost`
   и IP-адреса, остальные — `allowedHosts`.
2. **Пульт с телефона** (`/__slideria/remote/*`). Из сети пускает только телефон с пропуском (одноразовая
   ссылка из QR). В программе вход для телефона открывает `lan(deck)`, только к показываемой презентации.
3. **«Лицензии»** — только этому компьютеру. Раздел «Файл → Лицензии» студии и страница `/?licenses`
   (`src/engine/licenses-view.ts`, `licenses-page.ts`) берут данные из
   `/__slideria/licenses/data` (`plugins/licenses.mjs` → `licensesData`: программа, шрифты, библиотеки сервера и
   студии одной записью на версию, с текстами), лицензии Chromium — `/__slideria/licenses/chromium`. Старый адрес
   `/__slideria/licenses` ведёт на страницу.
4. **Данные для страниц** (только `GET`): `/__slideria/decks` — список (только этому компьютеру),
   `/__slideria/deck/<имя>` — презентация с адресами файлов этого сервера; ошибка в `deck.yaml` — 422 с текстом,
   нет такой — 404. Телефону вход в сети пропускает только показываемую презентацию (`desktop/lan.mjs`).
5. **Команды проекта** `/__htmlpptx/<команда>?deck=…`: только `POST`, только с этого компьютера, только со
   страниц этого же сервера (`Origin`). Ответ — JSON; ошибка — `{ error }` с кодом 400, сбой сборки — 500.

| Команда | Что делает |
|---|---|
| `list`, `create`, `read`, `save`, `delete` | презентации |
| `outline`, `apply` | операции правки для агента, MCP и плагинов ([OPS.md](OPS.md)) |
| `integrations`, `integrations-set`, `agent`, `journal`, `journal-add`, `scripts`, `script-read`, `script-save` | интеграции: кто на связи, что можно агентам, журнал, скрипты ([INTEGRATIONS.md](INTEGRATIONS.md)) |
| `chat-status`, `chat-connect`, `chat-disconnect`, `chat-send`, `chat-list`, `chat-read`, `chat-delete`, `chat-image` | чат «Агент» ([AGENT.md](AGENT.md), `server/agent.ts`): ключ Claude (страница его не видит), сообщение — ответ потоком событий (NDJSON), разговоры презентации. Ключ — `agentKeys` в настройках сервера: программа хранит его зашифрованным; без него — `ANTHROPIC_API_KEY` или в памяти. Адрес Claude API — `SLIDERIA_ANTHROPIC_URL` (тесты) |
| `checkpoint`, `checkpoints`, `checkpoint-read`, `discard` | контрольные точки: `checkpoint?kind=` — `auto` (до и после скрипта), `open` (студию открыли), `close` («Сохранить» при выходе); без него — своя (Ctrl+S). `discard?to=` — «Не сохранять» при выходе: файл как в точке, отброшенное — точкой `drop:`. В программе окно закрывается после ответа студии: `onBeforeClose` в `desktop/preload.cjs` |
| `asset`, `asset-text`, `assets-list`, `assets-trash` | файлы презентации |
| `font-list`, `font-save`, `font-use` | библиотека шрифтов |
| `library`, `library-put`, `library-delete` | своя библиотека студии |
| `import`, `import-pptx`, `bind-theme` | импорт |
| `export` | один HTML-файл |
| `firewall` | программа под Windows: разрешить пульт в брандмауэре |
