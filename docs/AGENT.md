# Чат «Агент» в студии

Модель по вашему выбору правит открытую презентацию по просьбе — прямо в студии, без отдельных программ: Claude,
ChatGPT, DeepSeek, Qwen, OpenRouter, Ollama на этом компьютере или свой адрес ([ниже](#сервисы)). Пишешь задачу («обнови
цифры по этому скриншоту», «сократи текст вдвое»), прикладываешь картинки, агент читает слайды и правит их теми же
операциями, что агенты по MCP ([OPS.md](OPS.md), [MCP.md](MCP.md)): каждая правка проверяется, видна на слайде сразу,
перед ней ставится контрольная точка. После правки, меняющей вид, агент смотрит на слайд картинкой и сам поправляет
вылезший текст и наложения ([ниже](#взгляд-на-слайд)).

## Где

Панель справа, на месте «Свойств»: ✦ в шапке, «Агент» в строке состояния, Ctrl+J (и из её поля — закрыть).
«Свойства» (Ctrl+Shift+2) встают обратно на её место. Ширина своя — тянется за границу.

- **Сообщение:** Enter — отправить, Shift+Enter — новая строка. Открытый слайд уходит вместе с сообщением
  (плашка «Слайд 5», ✕ — без него).
- **Картинки** (PNG, JPG, WebP, GIF, до 5 МБ, до 6 в сообщении): скрепка, Ctrl+V или перетаскивание на панель.
  Агент их видит и по просьбе ставит на слайд (картинка копируется в файлы презентации). Модель не видит картинки
  (так сказал сервис или она отказалась) — скрепки нет, подсказка у кнопки предлагает другую модель.
- **Пока агент работает:** видны его шаги («Прочитал слайд 5», «Правка объекта · слайд 5», «Посмотрел слайд 5») и ответ по мере
  написания. «Стоп» (кнопка или Esc) — останавливает; сделанные правки остаются.
- **Под ответом — карточка правок:** эскиз слайда, сколько правок. «Показать» — к слайду, «Вернуть» — как было до
  ответа, а то, что поправили после, остаётся (слияние трёх версий по точкам до и после).
- **Ctrl+Z** отменяет весь ответ агента одним шагом: вы сами попросили его в этом окне. Правки внешних агентов
  (по MCP) Ctrl+Z, наоборот, не трогает.
- **Голос** — микрофон в поле («Диктовать»): речь распознаётся на этом компьютере, текст встаёт в поле ([ниже](#голос)).
- **Модель** — в шапке панели: список — у самого сервиса (у Claude — Opus 5.5 по умолчанию, Sonnet 5.5, Haiku 5.5),
  моделей больше 12 — с поиском (Enter — первая подходящая). Выбор у каждого сервиса свой. Там же — «Сменить
  сервис…» и «Отключить ключ …» (у Ollama — «Отключить Ollama»).
- **Разговоры** — у каждой презентации свои: «+» — новый, часы — прошлые (открыть, удалить).

Уходите из студии после ответа агента — правки агента входят в «Сохранить изменения?» наравне со своими.

## Сервисы

Экран «Подключите модель»: сервис — кнопкой, под ней — чем он хорош и чего не умеет, поля — по сервису. Оплата — за
запросы по тарифам выбранного сервиса (Ollama — бесплатно). Подписка Claude или ChatGPT к сторонней программе не
подключается: с подпиской правят из Claude Desktop, Claude Code или Codex через MCP — они подключаются в один щелчок
в «Файл → Интеграции → Агенты».

| Сервис | Что нужно | Особенности | Куда уходит содержимое |
|---|---|---|---|
| Claude | ключ `sk-ant-…` ([где взять](https://platform.claude.com/settings/keys)) | видит картинки, лучше всех понимает оформление | Anthropic |
| ChatGPT | ключ OpenAI ([где взять](https://platform.openai.com/api-keys)) | видит картинки | OpenAI |
| DeepSeek | ключ ([где взять](https://platform.deepseek.com/api_keys)) | в разы дешевле; картинки видят не все модели | DeepSeek |
| Qwen | ключ Alibaba Cloud Model Studio, международный (Сингапур) | недорого; картинки видят не все модели | Alibaba Cloud |
| OpenRouter | ключ `sk-or-…` ([где взять](https://openrouter.ai/settings/keys)) | сотни моделей по одному ключу; в списке — только те, что вызывают инструменты, у каждой — видит ли картинки | OpenRouter |
| Ollama | адрес (`http://localhost:11434`), модель — из установленных | без ключа, оплаты и интернета; маленькие модели правят хуже, модель должна уметь вызывать инструменты (например, qwen3) | никуда — модель на этом компьютере |
| Другая | адрес API, совместимого с OpenAI, модель; ключ — если нужен | свой сервер, LM Studio, другие облака | на указанный адрес |

- **Ключ у каждого сервиса свой.** Подключили DeepSeek, потом Claude — ключ DeepSeek остаётся: «Сменить сервис…» →
  DeepSeek → «Подключить», ключ вводить не нужно («Ключ сохранён — можно не вводить»). У сервисов с сохранёнными
  настройками — зелёная точка на кнопке. «Вернуться к разговору» — без смены.
- **Проверка при подключении** — список моделей у сервиса (бесплатно): неверный ключ, нет связи, Ollama не запущена
  — понятным текстом под полями. У Ollama список моделей виден сразу, по мере ввода адреса.
- **Модель не приняла картинку** — ошибка «Модель «…» не видит картинки» и запоминается: дальше у этой модели нет
  скрепки, а картинки прошлых сообщений ей не уходят (вместо них — пометка в тексте).
- **Модель не умеет вызывать инструменты** (у Ollama — многие маленькие) — «выберите другую».

Ключи хранятся только на сервере программы — страница студии их не видит:

| Где запущено | Где ключи |
|---|---|
| Программа (Windows, macOS, Linux с хранилищем паролей) | `agent-keys.bin` в данных программы — все сервисы одним файлом, зашифрован системой (safeStorage: DPAPI, Связка ключей, GNOME Keyring или KWallet). Ключ Claude прошлых версий (`claude-key.bin`) подхватывается сам и при первой записи переносится |
| Программа на Linux без хранилища паролей | там же, зашифрован встроенным паролем Chromium — файл не читается как текст, но защита слабее; панель об этом говорит |
| `yarn dev`, `scripts/serve.mjs` | введённые в студии — в памяти до перезапуска сервера; ключ Claude — ещё из переменной `ANTHROPIC_API_KEY` |

**Что уходит выбранному сервису:** текст сообщения, приложенные картинки, данные открытого слайда (до 24 КБ, больше —
агент читает сам) и то, что агент прочитает инструментами, — в том числе картинки слайдов, на которые он посмотрит. Только когда вы пишете агенту. Ollama — никуда: модель
работает на этом компьютере. Запись голоса не уходит никуда: её распознаёт сама программа, а агенту уходит только
текст, если его отправить.

## Голос

Микрофон в поле сообщения — «Диктовать». Речь распознаётся на этом компьютере, без интернета; текст встаёт в поле
на место курсора и сам не отправляется — перед отправкой его можно поправить.

- **Первый раз** — карточка над полем: для распознавания нужна модель (GigaAM v3 со знаками препинания — Сбер,
  MIT; 156 МБ загрузки, около 215 МБ на диске). В установщик она не входит: голосом пользуются не все. «Скачать» —
  с GitHub, ход загрузки и «Отмена»; карточку можно закрыть — загрузка продолжится. Оборвалась — «Повторить»
  продолжает с того же места. «Указать файл…» — архив, скачанный на другом компьютере (ссылка — в карточке).
  Готово — «Начать запись».
- **Запись** — полоса над текстом: время, уровень звука, «Не уходит с компьютера»; микрофон красный, поле только для
  чтения. «Готово» (кнопка, Enter или микрофон) — текст в поле; «Отмена» (Esc) — как будто записи не было.
  Закрыли панель — запись останавливается, микрофон выключается. Через 10 минут — «Готово» само.
- **«Удалить модель»** — «Файл → Параметры» → «Голосовой ввод»: там же видно, сколько модель занимает на диске
  (подтверждение — в той же строке). Модель выгружается из памяти и удаляется с диска; микрофон снова предложит
  скачать модель.
- **Длинная запись** режется на паузах (куски по 12–20 с — той длины, на которой учили модель) и распознаётся по
  ходу: текст появляется в поле, пока вы говорите, а после «Готово» ждать только последний кусок — меньше секунды.

| Что | Как |
|---|---|
| Модель | `sherpa-onnx-nemo-ctc-punct-giga-am-v3-russian-2025-12-16.tar.bz2` из релиза `asr-models` на github.com/k2-fsa/sherpa-onnx; адрес, размер и SHA-256 — в `server/voice.ts` |
| Где | программа — `voice/` в данных программы; `yarn dev` — `node_modules/.cache/slideria-voice` |
| Загрузка | в своём потоке: архив идёт сразу в `download.part` (оборвалось — запрос `Range` с этого места), в SHA-256 и в распаковку (bzip2 — `unbzip2-stream`, tar — свой разбор: только нужные файлы, по имени без папок). На место модель встаёт только после проверки, архив затем удаляется. Не хватает места на диске — сказано до загрузки |
| Распознавание | движок sherpa-onnx-node (Apache-2.0, внутри — ONNX Runtime; в программе) в отдельном потоке сервера, 2–4 потока процессора. Модель загружается в память, когда начали запись (~1 с), — первая фраза не ждёт |
| Память | ~300 МБ, пока моделью пользуются; 3 минуты без записи — поток завершается. На Linux часть памяти остаётся за процессом сервера: её держит распределитель glibc и отдаёт при следующей загрузке модели (рост не копится) |
| Микрофон | AudioWorklet, 16 кГц, моно; шумоподавление браузера. В программе микрофон самой студии — без вопроса (`desktop/main.mjs`): запись начинается нажатием и видна полосой; слайды спрашивают, как раньше ([PERMISSIONS.md](PERMISSIONS.md)) |

Код: `server/voice.ts` (модель и распознавание), `src/studio/agent-voice.ts` (карточка, запись, нарезка на паузах —
грузится при первом нажатии на микрофон). Команды сервера — `voice-*` ([SERVER.md](SERVER.md)).

Тесты: `tests/unit/voice.spec.ts` — образец архива с раскладкой настоящего (`tests/fixtures/voice-model.tar.bz2`):
обрыв и продолжение, не тот архив, «Отмена», файл вручную; настоящая модель — если её уже скачали для `yarn dev`.
`tests/e2e/voice.spec.ts` — поддельный микрофон Chromium, распознавание — подставной текст (`SLIDERIA_VOICE_STUB`).
`tests/app` — микрофон студии без вопроса и распознавание в процессе сервера программы.

## Как устроено

`server/agent.ts` — цикл «модель → инструменты» (ответ потоком). Claude — SDK `@anthropic-ai/sdk`; остальные
сервисы — `server/agent-llm.ts`: пресеты (адрес, вид ключа, особенности, модель по умолчанию) и ход модели по
протоколу, совместимому с OpenAI (`/chat/completions` потоком, инструменты — `tools`, у ChatGPT —
`max_completion_tokens`). История разговора хранится в формате Claude и переводится на ходу: вызовы инструментов —
`tool_calls`, их ответы — сообщения `tool`, мысли не уходят; без картинок — текст строкой (DeepSeek не принимает
список частей). Инструменты у всех сервисов одни:

| Инструмент | Что делает |
|---|---|
| `read_presentation` | краткое содержание или один слайд целиком (как MCP) |
| `edit_presentation` | пакет операций с `expect` — ревизиями прочитанных слайдов (как MCP) |
| `format_guide` | справка по формату — `docs/skills/slideria-deck/SKILL.md` (в установщике тоже) |
| `use_attachment` | картинка из разговора → файл презентации, ответ — путь `./assets/…` |
| `view_slides` | картинки слайдов (PNG) в конечном виде, до 4 за раз, ширина 480–1280 (по умолчанию 960) — [ниже](#взгляд-на-слайд) |

Правки — `core.apply` с `by: { kind: 'agent', id: 'studio-chat', name: 'Агент' }`: точки до и после, запись
журнала («Версии» — сеанс «Агент», «Файл → Интеграции → Журнал»). «Что можно агентам» чата не касается — это
просьба самого пользователя. Студия вливает правки своего чата как свои (`Editor.agentAnswer`): весь ответ — один
шаг отмены; плашка внешних агентов и их подсказка на холсте правки чата не показывают.

Предел — 40 шагов «модель → инструменты» на ответ; ввод инструмента, оборванный на пределе длины, не выполняется.
Ошибки — понятным текстом: ключ отозван или на счёте нет средств («Подключить заново»), лимит запросов,
перегрузка, нет связи («Повторить»), модель не видит картинки или не вызывает инструменты. Сбой связи, лимит или
перегрузка до начала ответа — повтор (до двух раз, с паузой).

### Взгляд на слайд

Агент видит слайд так же, как агенты по MCP (`view_slides`, [MCP.md](MCP.md)): картинка слайда в конечном виде — все
шаги показа открыты, анимации доиграны. В подсказке модели — правило: после правки, меняющей вид (тексты, размеры,
расположение, новые объекты, оформление), посмотреть на результат и поправить вылезший или обрезанный текст,
наложения, нечитаемое. Заметки и правку пары слов смотреть не нужно.

| Что | Как |
|---|---|
| Когда предлагается | есть браузер для снимков и модель видит картинки. Модель картинок не видит (так сказал сервис) — инструмента и правила нет; отказ сервиса посреди ответа — модель запоминается такой, шаг повторяется без картинки, ответ не обрывается |
| Чем снимается | программа — скрытое окно Electron в главном процессе (`desktop/shot.mjs`): сервер программы просит его сообщением `call('shoot')` (`server/host.ts`). `yarn dev` и `scripts/serve.mjs` — Playwright (`scripts/pw-shot.mjs`: Chromium Playwright, иначе Chrome или Edge системы) |
| Скорость | первый снимок с запуском браузера — около 0,5 с, следующие — 0,2–0,3 с |
| Размер | 960 по ширине: мелкий текст читается, а картинка обходится модели примерно втрое дешевле, чем 1280 |
| В переписке | картинки — файлами `v….png` в папке разговора, в истории — ссылкой. Модели уходят снимки только текущего ответа; прошлые — пометкой «была раньше» (снова нужна — посмотрит снова): не платить в каждом запросе за устаревшие картинки |
| Сервисы OpenAI | ответ инструмента `tool` картинок не принимает — подписи там, а картинки с теми же подписями — следующим сообщением |

**Переписка** — `.slideria/chats/<имя>/<id>.json` (для панели и для модели) и картинки рядом, в папке `<id>/`. В файл
презентации и в экспорт не попадает; уходит в корзину вместе с презентацией (`.history/chats`) и возвращается с ней.

**Команды сервера** (`server/http.ts`, только POST с этого компьютера):

| Команда | Что делает |
|---|---|
| `chat-status` | подключена ли модель и какой сервис, модели сервиса (видят ли картинки), где ключи, пресеты для экрана подключения (у каких сохранены настройки) — ключей в ответе нет |
| `chat-connect` | подключить сервис `{ provider, key, url, model }` (проверка у сервиса — список моделей) и сделать текущим; без ключа — сохранённый; `{ key }` — ключ Claude, как раньше |
| `chat-probe` | модели по адресу, ещё не подключая `{ provider, url }` — Ollama: что установлено |
| `chat-disconnect` | отключить сервис `{ provider }` (по умолчанию — текущий): ключ и настройки удаляются |
| `chat-send?deck=` | сообщение `{ chat, text, images, slide, model }` — ответ потоком событий, строка JSON на событие: `chat`, `think`, `step`, `text`, `edit` (запись журнала), `error`, `done`. Закрыли запрос — агент останавливается |
| `chat-list`, `chat-read`, `chat-delete`, `chat-image` | разговоры презентации, разговор, удалить, картинка из разговора |

**Тесты** — на подставных сервисах: Claude (`tests/mock-claude.ts`: поток событий как у `/v1/messages`) и
совместимый с OpenAI (`tests/mock-openai.ts`: `/models`, `/chat/completions` потоком; без ключа — как Ollama), ходы
по сценарию теста. Адреса для сервера — `SLIDERIA_ANTHROPIC_URL` и `SLIDERIA_OPENAI_URL` (у сервера тестов —
`http://127.0.0.1:5191` и `http://127.0.0.1:5194/v1`; Ollama и свой адрес — какие ввели). `tests/unit/agent-llm.spec.ts`
— пресеты, ключи, перевод истории, ошибки; `tests/e2e/agent-providers.spec.ts` — экран подключения и меню;
`tests/app` — ключи в `agent-keys.bin` и перенос ключа прошлой версии. Взгляд на слайд: unit — снимок без браузера
(картинки, подписи, пометки вместо прошлых снимков, повтор без картинок у модели, которая их не видит);
`tests/e2e/chat.spec.ts` — настоящий снимок Playwright сервера тестов; `tests/app` — снимок главным процессом программы.
