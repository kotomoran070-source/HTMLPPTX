# Slideria — правила работы для агентов

Презентации как данные (`deck.yaml`), студия как PowerPoint, показ, экспорт в один HTML, PPTX и PDF, программа на
Electron, MCP для агентов. Что где лежит — README → «Структура»; как устроено — `docs/*.md` (компоненты, сервер, MCP,
операции, скорость, план).

## Общение

- Отвечать **по-русски**, коротко и по делу: что сделано, что проверено (с цифрами), что осталось.
- Пользователь пишет коротко и иногда со скриншотом — сначала понять, что именно он показывает, потом делать.
- Вопрос «есть ли смысл / что думаешь» — это вопрос: ответить рассуждением и рекомендацией, код не трогать.

## Объём правок

- Делать **только то, о чём попросили**. Заметил ещё проблему — сказать о ней отдельно и предложить, но не чинить
  молча и не расширять задачу.
- **Изменения интерфейса — сначала макет** (текстом или картинкой) и согласие пользователя, потом код. Исключение —
  мелочь внутри уже согласованного (подпись, отступ, состояние наведения).
- Пользователь отверг вариант — убрать его полностью, не оставлять «на всякий случай».

## Тексты интерфейса и код

- Тексты — по-русски, спокойно и без фамильярности, без «я/мы» от лица программы. Кнопки и пункты меню — как
  в PowerPoint, если там есть аналог.
- Комментарии в коде — по-русски, объясняют «зачем», а не пересказывают код. Стиль файла — как у соседних.
- Никаких идентификаторов моделей в коммитах, коде и документах.
- `:hover`-правила — только с классом у последнего элемента (без `X:hover > *` и `X:hover tag`): иначе каждое наведение
  пересчитывает стили по тегу (стережёт `tests/unit/hover-css.spec.ts`).
- Новая возможность для пользователя — строка в README (таблицы разделов студии), для агентов — `docs/OPS.md`,
  `docs/MCP.md`, справка формата `docs/skills/slideria-deck/SKILL.md`.

## Проверки: какие тесты гонять

Полный прогон долгий — **гонять то, что задевает правка**, а не всё подряд:

- типы: `npx tsc --noEmit -p .` (всегда перед коммитом);
- unit — быстрые: `npx playwright test --project=unit tests/unit/<файл>.spec.ts`;
- e2e — по файлу или по строке теста: `npx playwright test --project=e2e tests/e2e/<файл>.spec.ts:<строка>`
  (сервер на порту 5190 поднимает сам Playwright — он должен быть свободен);
- программа Electron: `xvfb-run -a npx playwright test --project=app tests/app/app.spec.ts -g "<имя>"`;
- скорость: `yarn perf` (см. README → «Замеры скорости», журнал — `docs/PERF.md`).

Упавший тест сначала проверить: падал ли он и до правки (старый тест, который давно не запускали) — сказать об этом
прямо, а не подгонять. Визуальные правки — смотреть снимком (Playwright), снимок для пользователя — с
`deviceScaleFactor: 2`.

## Сервер для ручной проверки

- Свой сервер — на **другом порту**, не 5190, и на тестовой копии презентаций:
  `SLIDERIA_DECKS=.tmp/test-decks node node_modules/.bin/vite --port 5192 --strictPort` в фоне, **PID — в
  `.tmp/serve.pid`**.
- Процессы останавливать **только по PID** (`kill $(cat .tmp/serve.pid)`), никогда по имени или шаблону (`pkill`,
  `killall`) — так можно убить чужой сервер или тесты.
- Свои временные презентации и скрипты — с префиксом `zz` (`.tmp/test-decks/zz…`, `zz-*.mjs`): их убирает уборка.

## Перед коммитом

```bash
rm -rf tests/e2e/zz* tests/unit/zz* presentations/zz* dist/zz* test-results .tmp/test-results zz-*.mjs zz-*.cjs .tmp/test-decks/zz*
node tests/prepare.mjs   # тестовые презентации — заново; не запускать, пока идут e2e
npx tsc --noEmit -p .
```

## Git

- Работать в выданной ветке; пуш — `git push -u origin HEAD:refs/heads/<ветка>`; pull request — только по просьбе.
- Коммит — по законченной задаче, сообщение по-русски: заголовок (что сделано) и пункты (что и зачем). Не дробить
  работу на множество промежуточных «контрольных точек».
- Чужую историю не переписывать (без `rebase`, `--amend` и `--force` на чужих ветках).

## Скорость

Решения об оптимизации — по замерам (`yarn perf`, `docs/PERF.md`), не на глаз. Уже найденное:
- бесконечные анимации и `transition` на тенях во время прокрутки — перерисовка слоёв на каждом кадре;
- `scrollTo({behavior:'smooth'})` на каждый щелчок колеса — рывки; для лент — свой плавный прокрутчик
  (`src/engine/hscroll.ts`);
- запись в стиль тем же значением всё равно пересчитывает стили — сравнивать перед записью.
